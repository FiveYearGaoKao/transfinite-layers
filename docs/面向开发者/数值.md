# 数值

> 面向开发者。本文说明游戏里"数"怎么表示、算一次要多久、有哪些常量范围。以【代码】为准,如有出入请修正本文档。
> 序列化(存档里的 Decimal 格式)见 [存档.md](./存档.md);加成管道见 [effect机制.md](./effect机制.md);缓存与实测基线见 [性能.md](./性能.md)。

## 一、Decimal(break_eternity.js)

- **表示**:`value = sign × 10^10^…^mag`(共 `layer` 个 10),即 `sign`/`mag`/`layer` 三个字段。
  `layer=0` 时就是一个普通 double(存的是 `mag`,`save/save.ts` 用它做位精确往返)。
- **值域**:最大约 `10^^(1.79e308)`(`Decimal.dNumberMax`),最小约 `1/(10^^(1.79e308))`;
  `layer` 加到约 `9.007e15`(`dLayerMax`)以上时 `+1` 已是安全操作。
  `Infinity`/`NaN` 用 `Decimal.dInf`/`dNaN` 表示,判断用 `isFinite()`/`isNan()`。
- **构造**:`new Decimal(number | string | Decimal)`;回调参数可以收 `DecimalSource`(宽松输入),
  但**输出必须是 `Decimal`**(见 [开发规范.md](./开发规范.md) §六)。字符串支持 `'1e100'`、`'1e1e100'`、`'10^^8.5'`。
- **常量**(重复使用它们,避免到处 `new Decimal(0)`):`Decimal.dZero` / `dOne` / `dTwo` / `dTen` / `dInf` / `dNaN` / `dNumberMax`。

### 本项目常用的方法

| 类别   | 方法                                                                                       |
| ------ | ------------------------------------------------------------------------------------------ |
| 运算   | `add` `sub` `mul` `div` `neg` `abs` `recip` `pow` `root` `log10` `log` `ln` `exp`          |
| 比较   | `lt` `lte` `gt` `gte` `eq` `cmp` `min` `max` `clamp`(静态版同名,`Decimal.max(a, b)`)      |
| 取整   | `floor` `ceil` `round` `trunc`(`floored(curve)` 用 `floor` 把价格取整)                     |
| 指数塔 | `layeradd10` `tetrate` `iteratedexp` `slog` `iteratedlog`(软上限的 `height` 就是 `layeradd10`) |
| 数组和 | `sumArithmeticSeries` `sumGeometricSeries` `affordArithmeticSeries` `affordGeometricSeries` |
| 显示   | `toNumber` `toExponential` `toString`(`tools/format.ts` 的 `format` 是唯一展示入口)         |
| 精确   | `Decimal.fromComponents_noNormalize(sign, layer, mag)`(只给读档用,普通代码不要碰)           |

### 精度与相等

- `layer ≥ 1` 的 Decimal 只有约 16 位有效位:数量级大到 `1e16` 以上时"k 与 k+1"本身就不可分辨,
  比较数量用相对误差(`scripts/helpers.ts` 的 `sameCount`),不要用 `eq`。
- `toString`/`fromString` 对 `|mag| < 1` 会丢约 1 ulp;存档因此对层0走 `fromComponents_noNormalize`(见 存档.md)。
- 字面量(number)可以直接参与比较与运算(`x.gte(1e10)`),不需要先包一层 `new Decimal`。

### 不可变与响应式

- **所有运算都返回新对象,游戏代码一律整体替换**(`player.x = player.x.add(y)`);
  `normalize()`/`fromComponents()` 会**就地修改 `this`**,游戏代码禁止调用。
- 因此 `data/player.ts` 给 `Decimal.prototype` 打了 Vue 的跳过标记(`__v_skip`):Decimal 不进响应式代理。
  实测(真实存档、整帧生产+自动化)去掉代理后帧耗时约减半,且游戏状态逐位不变;详见 性能.md。
  前提就是上一条"Decimal 从不就地修改"——玩家可见数值的更新靠**属性赋值**触发,而不是靠 Decimal 内部变化。

## 二、运算成本

- **一次 Decimal 运算约 1 µs 量级;number 的读写是 ns 级**(差三个数量级)。热路径是"每帧 × 每层 × 每个物品",
  所以:能被缓存的量必须缓存,能在同一帧内复用的量不要重复求值。
- 实测口径(真实存档 `v0.1.5`,开发构建,详见 性能.md §三):
  `dimensionCostAt` 约 12.6 µs、`maxBuyable` 约 0.035 ~ 0.07 ms、
  槽位组合值(`slotValue`)约 4 ~ 25 µs(与它读多少已购数、跑多少 Decimal 运算有关)。
- **求值次数靠"帧内缓存"消除**(`compute/frameCache.ts`):新增会被反复读的量时,给它一个具名槽位 +
  合适的 `scope`,而不是在公式里现算(缓存契约与 `clearFrameCache()` 的调用点见 性能.md)。
- **`scope` 决定帧内缓存的键**(`defineSlot(id, init, scope)`),按"值可能依赖什么"选:
  - `'item'`(缺省):值可依赖层级与物品id,键为"层级键+物品id";
  - `'layer'`:值只依赖层级(不读 `ctx.id`),键为层级键 —— 同层所有维度/物品共用一份;
  - `'global'`:值与层级、物品都无关,键为空。
  声明 `'layer'`/`'global'` 是承诺:开发构建会在首次解算时用另一个上下文对撞校验,不成立就报错。

## 三、常量范围(设计假设)

写代码时**可以依赖**下面这些范围;超出范围的输入不需要专门处理。

| 量                 | 范围                                      | 出处 / 说明                                                            |
| ------------------ | ----------------------------------------- | ---------------------------------------------------------------------- |
| `player.base`      | 2 ~ 10 的整数                             | 序数进制;只能通过因子转换机制减小,不通过它以外的途径改变(`INITIAL_BASE`) |
| 活跃层级数         | 一般不超过 256                            | 每帧遍历/坐标位数/统计页的规模假设                                     |
| 每层维度数         | 4 ~ 9                                     | 初始 4(`DIMENSION_COUNT`),元维度提升机制可提高上限;按层取 `L.dimensions.length` |
| 价格软上限幂次     | `> 1`                                     | `priceCap:power` 基准 2;`cap` 的求逆要求 `power > 0`                     |
| 维度生产软上限幂次 | `< 1`                                     | `dimCap:power` 基准 0.8;同上,逆运算是 `softCapValue(x, 阈值, 1/power, 高度)` |
| 软上限高度         | 价格=1、维度生产=1、挑战目标=0            | `SOFT_CAP_HEIGHT` 与各自声明处;`height` 是 `layeradd10` 的次数           |

- **知识升级价格是特例**:用 `constantCurve` 显式常量底数声明,**不经过效果管道**
  (没有软上限、也没有任何加成槽位),并且**不受 `player.base` 影响**(见 `compute/knowledge.ts`)。
- 新增数值时优先复用 `data/constants.ts` 的常量,不要在别处再写一份字面量。

## 四、检查清单

1. 新字段/新公式里的数是不是 `Decimal`?回调的返回值是不是 `Decimal`(不是 `DecimalSource`)?
2. 有没有用 `new Decimal(0)`/`new Decimal(1)` 这类常量?能换成 `Decimal.dZero`/`dOne` 就换。
3. 这个值一帧内会被读很多次吗?是的话给它一个具名槽位并选对 `scope`。
4. 有没有就地修改 Decimal(`normalize()`/直接写 `.mag`)或对 Decimal 调用会改 `this` 的方法?
5. 这个值的量级会不会超过 `1e16`?会的话比较用相对误差,不要用 `eq`。
6. 存档结构改动是否处理了 `initializeSave` + load 兜底(见 [存档.md](./存档.md))?

> 反例(禁止):
>
> - 用裸 `number` 存点数/价格/产量(`number` 只用于 id、索引、开关、百分比这类小整数);
> - 在 `static` 效果或帧内缓存里读"每帧会变的量"(见 性能.md);
> - 为了"省一次构造"而就地改一个已经存进 `player` 的 Decimal。
