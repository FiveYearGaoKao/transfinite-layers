# 架构

> 面向开发者。本文描述代码目录与依赖方向。以【代码】为准,如有出入请修正本文档。

## 一、技术栈

- Vue 3.5 + Vite 7 + TypeScript 5.9,`vue-tsc` 负责类型检查(不要用 `tsc`,`.vue` 会报错)。
- `break_eternity.js`:大数 Decimal,支持指数塔。
- `lz-string`:存档压缩(base64)。
- `@/` 别名 → `src/`。

## 二、目录结构(src/)

```
tools/      纯函数、零依赖,且是被多处复用的"算法型"函数(ordinal坐标/softCap软上限/format格式化/utils比较/quiz数学题生成)
data/       类型、常量与运行期缓存(player/types/constants/story/changelog/temp运行期缓存/log日志)
save/       存档(序列化/校验码/迁移/rng种子随机)
access/     只读访问player的便捷函数(layerGraph层级结构权威/索引)
compute/    只读计算,不写状态(effects加成管道/dimensions/energy/prestige/crossLayer跨层/upgrades/buyables/buying/knowledge/infinity/softCap/frameCache帧内缓存/layerContent)
logic/      写状态(update生产/layerStructure层级结构变更/purchase/automations层级自动化/metaAutomations元层自动化/achievements/challenges/reset/knowledge/infinity/debug/commands)
meta/       元重置层注册表(infinity等)
app/        顶层应用外壳/UI编排(根层):主循环/设置/新闻/运行时对话框/共享UI动作/指令执行/快捷键/导航/资源栏注册表
components/  UI(通用bars + features各页面)
```

> `app/` 与 `components/` 共同组成最顶端的 UI 外壳(`app/` 放编排:主循环/设置/对话框/指令/快捷键;`components/` 放页面与栏位组件,可引用 `app/*`)。
> `App.vue` 与 `main.ts` 因是 Vite 入口,保留在 `src/` 根。
> 运行期缓存(`data/temp.ts` 的临时层与调试开关)与日志(`data/log.ts`)放在 `data/`,避免 `access`/`compute`/`logic` 反向引用 `app`。

## 三、依赖方向(铁律)

```
tools → data → save/access → compute → logic → meta → app(ui)
```

- **单向**:禁止向上引用。
- **compute 只读**:计算函数只读状态并返回结果,绝不写状态。已知且**唯一**的例外是 `compute/knowledge.ts` 的 `addKnowledge`
  (知识收入经 `knowledgeGain` 管道后直接加到 `player.knowledge`;调用方 `logic/commands.ts`、`logic/achievements.ts`),
  它是"先经管道再落账"这一个动作,拆开反而要在每个调用点重抄一次管道。
- **重置先算后写**:`doReset` 先算收益再统一写。
- **例外/注意**:
  - `access` 里极少数写便捷函数(如 `addAmount`)属于例外;
  - **`components/*.vue` → `app/*`**(栏位与页面组件引用 `app` 的共享动作/设置/对话框)是既定的向上引用,`app/` 与 `components/` 同属最顶端外壳,不视为违反单向性;
  - UI 编排模块(如 `app/saveActions`/`app/commandRunner`/`app/uiActions`)在顶层 `app/`,可同时引用 dialog(ui) 与 logic;
  - `tools/` 放被多处复用的"算法型"纯函数(零项目依赖,可只引用 break_eternity);仅在某文件内部使用的纯函数不必强迁 tools,留在其所属层(读效果槽/玩家状态的游戏侧包装放 `compute/`);
  - 指令系统按依赖层拆分:`app/commandRunner`(UI编排) / `logic/commands`(签到答题逻辑) / `logic/quizBank`(题库) / `tools/quiz`(数学题纯函数生成);
  - `import type { ... }` 只在类型检查期存在,不构成运行期依赖,允许向上引用(如 `tools/ordinal.ts` 引用 `data/types.ts` 的 `LayerId`);
  - **除上述 UI 外壳与已标注例外之外,已知的向上引用只有下面三条,新增前先想清楚能不能反过来**:
    - `save/save.ts` → `logic/achievements.ts`(`unlockAchievementById('s15')`,校验码失败时解锁隐藏成就)
      与 `logic/metaAutomations.ts`(读档时 `sanitizeMetaAutomations` 兜底配置形状):读档与"写状态"天然耦合在存档入口;
    - `logic/achievements.ts` → `app/news.ts`(隐藏成就 s12 需要新闻条数 `NEWS_COUNT`);
    - `meta/infinity.ts` → `components/features/infinityLayer.vue`(元层注册表直接挂页面组件,`app/App.vue` 用 `<component :is>` 渲染)。
  - 除上述之外,"谁引用谁"必须是单向的:**跨层引用一律只往下看**。跨层关系不要靠"反正能跑"来维持——
    `logic/infinity.ts` 判定无限挑战用的是 `access/challengeState.ts` 的 id 约定(`isInfinityChallenge`),
    而不是去引用挑战注册表(那会形成 `logic/challenges ↔ logic/infinity` 循环)。

## 四、核心机制速览

- **数值口径**:所有游戏数值都是 break_eternity 的 `Decimal`(表示、常用 API、运算成本、常量范围见 [数值.md](./数值.md));
  Decimal 不参与 Vue 响应式(`data/player.ts` 给原型打了 `__v_skip`),前提是"Decimal 一律整体替换、从不就地修改"。
- **加成管道**:见 [effect机制.md](./effect机制.md),所有数值加成经 `registerEffect` 注册、由 `applyTo`/`slotValue` 读取。
- **性能与帧内缓存**:见 [性能.md](./性能.md)。价格/购买数量由 `compute/curves.ts` 的曲线四件套(正/逆/和/和逆)
  加 `compute/buying.ts` 的"解析求解 + 有界校验(回退通用搜索)"给出,
  软上限阈值/幂次与**所有槽位组合值**走 `compute/frameCache` 的帧内缓存。
  **新增写状态时必须检查该文档的缓存契约**:改变被缓存值的写操作要调用 `clearFrameCache()`。
- **注册表模式**:升级/可购买/自动化/成就/挑战/知识升级/元层/指令都是"定义数组+注册+访问函数"。
  成就用 `trigger` 声明触发时机(缺省 `'frame'` / `'reset'` / `'infinity'` / `'manual'`),`logic/achievements.ts`
  在模块加载时按它分桶,帧循环只遍历 frame 那批;`'manual'` 没有可判定的条件,只能由 `unlockAchievementById` 触发。
- **购买防呆**:层级0 花光点数且本层没有任何维度后就再也没有产出(典型:iu22 把加倍器降到 1 价,在"无限重置后的1点开局"买它);
  `compute/buying.ts` 的 `purchaseStallsLayer0` 把这种购买直接视为"买不起",手动与自动化共用同一判定(买维度不受限,它正是恢复产出的手段)。
- **层级系统**:见 [层级系统.md](./层级系统.md)。坐标是**绝对编号**(规范形式:去前导零,键经 `layerKey`),只表示槽位;
  高度由 `level` 承担;阶 = 自己槽位所在位的权重([5] 与 [1,5] 都是 0 阶);
  **层级结构与相邻关系的权威实现在 `access/layerGraph.ts`,结构变更唯一入口是 `logic/layerStructure.ts`**;
  重置/跨层/挑战绑定等规则见该文档。
- **层级0特殊**:无重置按钮、维度1产点数(其余层产能量)、energy恒0、永不清除。
- **无限重置**:层级0点数≥1.79e308 时可用(快捷键I),IP=floor(基础公式经 `infinityGain` 管道);删除层级0以外的全部 0 阶层级并清空普通挑战记录,成就/知识/无限数据保留(见 `logic/infinity.ts`)。
  自动化配置整体清空(`resetAutomationsForInfinityReset`),但无限里程碑 im6 解锁后保留层级0那一份(im6 同时让层级0的维度/可购买自动化不再依赖层级1的 u4/u5,见 `dimsAutoUnlocked`/`buyablesAutoUnlocked`)。
  元层 onTick 每帧累计"本次无限经历的时间"(`player.infinityRunTime`);无限重置时记录最短时间(`infinityBestResetTime`)、最佳无限点数/秒(`infinityBestRate`)、最近 10 次重置的用时/获得/速率(`infinityResetLog`)并归零本次时间,总无限点数(`totalInfinityPoints`)累计不消除——供 IU33 等效果与统计页使用。
- **无限里程碑**:注册表在 `compute/infinityMilestones.ts`(定义数组+效果经管道注册),解锁态由 `player.infinityResets` 派生(只增不减,不占存档字段);纯解锁型里程碑不填 effect(im2 挑战不强制清空升级、im3 批量完成挑战、im6 层级0自动化保留、im10 自动解锁新层级、im15 自动无限重置),数值型走管道(im1 `dimensionMult`、im5 `infinityGain`),im8 改 `doInfinityReset` 的挑战记录处理,im100 的被动 IP 由 `logic/infinity.ts` 的 `updateInfinityMilestones` 每帧结算。
  跨过阈值时 `doInfinityReset` 会写一条"解锁无限里程碑"日志(定义里的 `unlockHint` 作为引导追加在后)。自动解锁新层级与自动无限重置都复用层级自动重置的条件判定(`logic/automations.ts` 的 `autoResetConditionsMet`)。
- **元维度提升**:解锁于无限升级 iu25,UI 是无限页的 `[元声望]` 子标签。次数存 `player.metaDimensionBoosts`(只增不减,任何重置都不清除);
  每层的维度数量由 `compute/metaDimension` 的 `dimensionCount()` 给出(= `min(4+次数, 8)`,上限见 `META_DIMENSION_MAX_COUNT`),维度指数加成作为 `static` 的 `add` 效果注册在 `dimensionExponent` 上;
  执行见 `logic/metaDimension.ts` 的 `doMetaDimensionBoost`(先把存活层级补到新维度数,再 `doInfinityReset(true)` 强制无限重置且不给 IP)。
  **因此凡是"新建层级/临时层"或"重建维度数组"的代码路径都必须传 `dimensionCount()`**(`data/types.ts` 的 `initializeDimensions`/`initializeLayer` 的缺省值只用于空白档),否则元维度提升解锁的维度会被那次重置吃掉。
- **元层自动化**:`logic/metaAutomations.ts`(注册表 `META_AUTOMATIONS`,**数组顺序即每帧执行顺序**)。与层级自动化的差别:配置不按层级存放,存在 `player.metaAutomations[id]`(全局唯一实例,不随无限重置清空),解锁由各机制自己判定(成就/知识/里程碑都行),每帧由 `updateMetaAutomations` 各跑一次。配置形状由 `MetaAutomationDef.configKind`('buy'/'reset')声明,决定用哪个配置UI组件与哪套读档兜底(`sanitizeCfg`);`hideMult` 让配置编辑器隐藏该自动化下恒成立的"倍率"条件(如"自动解锁新层级"的临时层点数恒为0)。
  "自动解锁新层级"(`unlock`):里程碑 im10 解锁,默认开启并预置点数条件;判定经 `findUnlockableTempLayer`(临时层+该阶内容已定义+`canReset`),执行经 `reset.ts` 的 `autoUnlockTempLayer`(与手动点临时层重置等价,但不切视角——视角切换是手动重置在 `resetLayerConfirm` 里的后续动作);挑战进行中不禁用。
  层级自动化的配置形状同理由 `AutomationDef.configKind` 声明;自动化页只按 `configKind` 选组件(`autoBuyConfig.vue`/`resetAutoConfig.vue`),不再按 id 分支。卡片外壳 `autoCard.vue` 只处理公共部分(标题/未解锁徽标/总开关/优先级)。
- **自动化的配置补齐**:`updateLayerAutomation` 经 `getLayerAutomation` 取配置,缺失时按全局配置模板(无模板则默认值)创建——自动化不依赖"玩家打开过该层页面",新解锁层级与无限重置后的层级都能立即续跑。
- **一帧顺序(全局三段式)**:结构阶段(尝试加深世界 `promoteWorldDepth` → 同步临时层)→所有层生产(高→低)→元层 onTick→元层自动化(全局唯一实例,如自动无限重置/自动解锁新层级;排在层级自动化之前,因为元层重置会清空层级自动化配置)→所有层自动化(低→高,即时结算)→挑战锁定→挑战C5等每帧惩罚→成就检查→答题储存结算。
  自动解锁新层级排在自动无限重置之后:同一帧两者都满足时先无限重置,否则自动解锁会把层级0点数清回1、使本次无限重置被跳过。

## 六、新系统接入清单

新增玩法系统遵循:类型定义(`data/types.ts`)→ 注册表定义 → 效果经 effects 管道 → UI 组件挂到主标签 → 存档字段(含 load 兜底)。
