# 开发规范

> 面向开发者。提交代码前必读,违规的 PR 会被打回。

## 一、常用命令

```sh
npm run dev          # dev server (vite)
npm run build        # 删dist → type-check + build-only(并行)
npm run type-check   # vue-tsc --build(不要用 tsc;含 src 与 scripts 两个工程)
npm run lint         # eslint . --fix
npm run format       # prettier --write src/
npm run check        # 跑全部验证脚本(价格/效果/存档/成就)
```

## 二、代码约定

1. **中文注释**;每个新函数前加**中文 jsDoc**。
2. **注册表模式**:升级/可购买/自动化/成就/挑战/知识升级/元层/指令都是"定义数组 + 访问函数"。
   类型 id 由注册表所在模块导出常量(如 `logic/automations.ts` 的 `AUTO_DIMS_ID`),注册表、访问函数与 UI 都引用常量,不要手写类型字符串。
3. **依赖单向**;compute 层只读(见 架构.md)。运行期缓存/日志放 `data/`(`data/temp.ts`/`data/log.ts`),不要从 `access`/`compute`/`logic` 反向引用 `app`。
4. 纯函数放 `tools/`;读效果槽/玩家状态的游戏侧包装放 `compute/`。
5. **数字用 Decimal**(break_eternity.js),禁止裸 number 存大数。
6. 存档结构改动需处理 `initializeSave` + load 兜底(必要时 migration)。
7. UI 新颜色用 `var(--...)` 主题变量;按钮用"类型 + 状态"双 class(见 style.css)。
8. 修改前先看相关文件现状;改完跑 `npm run type-check`、`npm run lint`、`npm run build`。
9. 与策划歧义时以策划为准,并询问用户确认。
10. **层级相关改动必须先读 [层级系统.md](./层级系统.md)**:
    - 遍历层级用 `access` 的顺序 API(`getOrderedLayers`/`forEachLayer`),禁止依赖 `Object.keys(player.layers)` 的键序;
    - 层间关系只经 `prevLayer`/`nextLayer`/`levelGap`,不要另写坐标算术;
    - 坐标是规范形式(去前导零,与 layerDepth 无关),键一律经 `layerKey` 生成与查找,不要手写 `pos.toString()`;
    - 阶是"自己槽位所在位的权重"(`[5]` 与 `[1,5]` 都是 0 阶),窗口是 `(祖先层序列, 阶)`,不要按坐标位数推断;
    - 增删层级键只允许出现在 `logic/layerStructure.ts`;挑战等对层级的引用写**高度**而不是坐标。
11. **文档只写"现在该怎么做"**(规则、做法、为什么这样做),不写变更史、不写"以前怎样是错的";
    版本变更记录只写在 `data/changelog.ts`(约定见 §三)。
12. **加成相关改动必须先读 [effect机制.md](./effect机制.md)**,并遵守其中的契约:
    - 数值点的 id 就是修饰目标,一一对应;禁止让两个含义共用一个 target;
    - 槽位一律 `defineSlot` 具名注册,禁止在调用点临时构造槽位对象,禁止手写 `{ pos: [0], id: 0 }`(ctx 可省);
    - 数值回调返回 `Decimal`;软上限一律用 `cap` 效果类型注册,禁止在公式里直接调 `softCap`/`softCapValue`;
    - 价格/挑战目标的底数只能经 `compute/curves.ts` 与 `upgradeCost` 读取,物品与目标声明禁止直接读 `getBase()`;
    - 价格/目标声明成 `curve`(四件套按需给),并让物品提供 `sum`/`sumInverse`;
    - 效果默认 dynamic,标 `static` 就等于承诺"只依赖购买/解锁/层级结构"。
13. **验证脚本放 `scripts/`**(不参与构建,但参与 `npm run type-check`,见 `tsconfig.scripts.json`):
    - 共用部分都在 `scripts/helpers.ts`:断言(`check`/`reportChecks`)、把开发构建的自检告警变成断言
      (`captureErrors`)、游戏引导(统一导入各系统的注册模块)、构造测试状态
      (`loadRealSave`/`freshSave`/`ensureLayer0Order`);
    - 跑单个脚本:`node scripts/run-ts.mjs scripts/checkXxx.ts`;跑全部:`npm run check`;
    - **按改动内容决定跑什么**(拿不准就把 `npm run check` 全跑):

    | 改动内容                                   | 必跑                         |
    | ------------------------------------------ | ---------------------------- |
    | 价格/曲线/挑战目标/买最大                  | `npm run check:pricing`      |
    | 效果槽位/数值点/软上限/`frameCache`        | `npm run check:effects`      |
    | 存档字段/`save`/`validate`/`checksum`/迁移 | `npm run check:save`         |
    | 成就(新增、改触发时机或条件)               | `npm run check:achievements` |
    | 其它(层级结构、跨层流程、新机制)           | `npm run check`              |
    | 改了数值,想看进度趋势                     | `node scripts/run-ts.mjs scripts/sim.ts 分钟数 步长秒 打印间隔秒`(见 [测试与平衡.md](./测试与平衡.md)) |
    - 新机制先补一个脚本再改代码:对撞式断言(与独立裁判/暴力枚举/往返对撞)比"跑一遍没报错"有价值得多;
    - 只改单个文件的纯文案/纯样式改动跑 `npm run type-check && npm run lint && npm run build` 即可;
    - 脚本要能被重复使用:一次性探针不要留在 `scripts/`,留下的每一行都要有后续用途。

## 三、版本号、更新记录与发布

`gameVersion`(`data/constants.ts`)与 `CHANGELOG`(`data/changelog.ts`)同步维护。

1. **一次改动至多升一个版本**(`v0.1.2` → `v0.1.3`);非特殊情况不要在同一批改动里连升多个版本。
2. **修 bug 与加新机制都要升版本号**:一批改动 = 一个版本号 = 一条 changelog。只有纯内部改动(重构、注释、文档、脚本)不升版本号。
3. changelog 只写**玩家能感知到的变化**,按版本从新到旧排列;写不出该写什么时**可以不写**(宁缺毋滥)。
4. 新机制**不写具体数值/公式**(阈值、倍率、公式放到游戏内说明与 [玩法指南](../面向玩家/玩法指南.md)),只写机制本身与它带来什么。
5. 对**已有内容**的平衡性调整要写(改了什么、往哪个方向调)。
6. 仅在开发环境可见的内容(调试入口、调试指令等)**不写**。
7. "旧存档可以正常加载"是正常行为,**不写**;只有**什么情况无法迁移**(需要玩家手动处理、或某类旧档数据会丢失/失真)才写。

### 发布与分支

两条线各一个分支,**推送到哪个分支就发布哪条线**(CI 见 `.github/workflows/deploy.yml`):

| 分支   | 线     | 发布路径                    | 分支上的 `gameVersion`         |
| ------ | ------ | --------------------------- | ------------------------------ |
| `main` | 正式版 | `/transfinite-layers/`      | 已发布的稳定版本               |
| `beta` | 测试版 | `/transfinite-layers-beta/` | 正在开发的下一个版本(未平衡)   |

- 日常开发提交到 `beta` 并推送(推送 = 发布测试版);一批内容平衡好、终局确定后合入 `main` 并推送(推送 = 发布正式版)。
- CI **每次都会同时构建两条线**再整站部署(两个路径在同一个 Pages artifact 里):只推 `beta` 不会动到正式版。`beta` 分支必须存在,否则构建失败。
- 测试版由 `.env.beta` 的 `VITE_BETA=true`(`vite --mode beta`)标记,与正式版的差别只有三处:
  - `base` 为 `/transfinite-layers-beta/`(见 `vite.config.ts`);
  - `storagePrefix`(`data/constants.ts`)带 `-beta` 后缀 → **测试版与正式版的存档、设置互不相通**;
  - 标题与"关于游戏"页标注"测试版"。
- 本地构建:正式版 `npm run build`;测试版 `npm run build:beta`(输出 `dist/transfinite-layers-beta`,可与正式版产物并存)。

## 四、代码风格(lint/prettier)

- 无分号、单引号、行宽 ≤100。
- 未使用变量前缀 `_` 抑制 ESLint 错误。
- `vue/multi-word-component-names` 已关闭。

## 五、UI 规范

- 并列的同类型组件(升级/可购买/成就/挑战卡)大小与子节点相对位置尽量固定一致。
- 按钮体系:**类型 class 决定大小**(subTab/prestige/buyable/upgrade/mainTab/toggle),
  **状态 class 决定颜色**(selected/affordable/bought/toggle-on/toggle-off/meta),全局在 style.css。
- 隐藏成就未解锁时描述显示 `???`,但卡片尺寸与普通成就一致。

### 栏位尺寸与移动端适配

改界面前先看这张表(改尺寸时**同时**改这里与对应 `.vue` 的 `<style>`):

| 栏位     | 组件                     | 常规尺寸                                     | 窄屏/矮屏(`max-width:700px` 或 `max-height:500px`) |
| -------- | ------------------------ | -------------------------------------------- | -------------------------------------------------- |
| 新闻栏   | `newsBar.vue`            | 100% 宽 × 32px 高(文字横向滚动)              | 不变                                               |
| 资源栏   | `resourceBar.vue`        | 100% 宽,4 行网格(条目多时横向滚动)           | 不变(靠横向滚动,不换行)                            |
| 导航栏   | `navigatorBar.vue`       | 150px 宽 × 100% 高,按钮纵向排列              | 100% 宽,按钮横向换行,高 ≥40px(按钮 36px 高)        |
| 主内容区 | `App.vue` 的 `#realMain` | `flex:1`,纵向滚动;中区为**横向**(导航栏在左) | 中区改**纵向**(导航栏在上、日志栏在下)             |
| 日志栏   | `logBar.vue`             | 300px 宽 × 100% 高(右侧)                     | 100% 宽 × 100px 高,贴底(边框改为上边框)            |
| 工具栏   | `toolBar.vue`            | 100% 宽 × 32px 高(图标按钮 32px、指令框占满) | 不变                                               |

- 断点只有一处:`@media (max-width: 700px), (max-height: 500px)`,分别写在 `App.vue` 与各栏位组件内(没有集中的布局文件)。
- 新增栏位时同步:`App.vue` 的 `#header`/`#center`/`#footer` 三段 + 自己的 scoped 样式 + 本表一行。
- 尺寸改动后必须在窄屏与矮屏(横屏)各看一眼:主内容区不能被挤成 0 宽,日志栏不能遮住内容。

## 六、类型标注

- 能判断具体类型的参数**不要用 `DecimalSource`**(它是 `number|string|Decimal` 的宽松类型)。
  例如 `resetGain` 返回 `Decimal`,成就 `'reset'` 触发的 `isCompleted(ev)` 里 `ev.gain` 就应标 `Decimal`。
- **输入宽松、输出严格**:被注册表/管道调用的数值回调(`init`/`value`/曲线三方法/`cost`…)**必须返回 `Decimal`**;
  调用方传入的数值参数可以收 `DecimalSource`(便于写字面量)。读取路径不得再包 `new Decimal(...)` 归一化。
- 层级引用一律用 `LayerRef`(`LayerId | Layer`,见 data/types.ts);需要接受 undefined 的调用处显式写 `LayerRef | undefined`。
