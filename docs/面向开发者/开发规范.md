# 开发规范

> 面向开发者。提交代码前必读,违规的 PR 会被打回。

## 一、常用命令

```sh
npm run dev          # dev server (vite)
npm run build        # 删dist → type-check + build-only(并行)
npm run type-check   # vue-tsc --build(不要用 tsc)
npm run lint         # eslint . --fix
npm run format       # prettier --write src/
```

## 二、代码约定

1. **中文注释**;每个新函数前加**中文 jsDoc**。
2. **注册表模式**:升级/可购买/自动化/成就/挑战/知识升级/元层/指令都是"定义数组 + 访问函数"。
3. **依赖单向**;compute 层只读(见 架构.md)。
4. 纯函数放 `tools/`;读效果槽/玩家状态的游戏侧包装放 `compute/`。
5. **数字用 Decimal**(break_eternity.js),禁止裸 number 存大数。
6. 存档结构改动需处理 `initializeSave` + load 兜底(必要时 migration)。
7. UI 新颜色用 `var(--...)` 主题变量;按钮用"类型 + 状态"双 class(见 style.css)。
8. 修改前先看相关文件现状;改完跑 `npm run type-check`、`npm run lint`、`npm run build`。
9. 与策划歧义时以策划为准,并询问用户确认。

## 三、代码风格(lint/prettier)

- 无分号、单引号、行宽 ≤100。
- 未使用变量前缀 `_` 抑制 ESLint 错误。
- `vue/multi-word-component-names` 已关闭。

## 四、UI 规范

- 并列的同类型组件(升级/可购买/成就/挑战卡)大小与子节点相对位置尽量固定一致。
- 按钮体系:**类型 class 决定大小**(subTab/prestige/buyable/upgrade/mainTab/toggle),
  **状态 class 决定颜色**(selected/affordable/bought/toggle-on/toggle-off/meta),全局在 style.css。
- 隐藏成就未解锁时名称/描述显示 `???`,但卡片尺寸与普通成就一致。

## 五、类型标注

- 能判断具体类型的参数**不要用 `DecimalSource`**(它是 `number|string|Decimal` 的宽松类型)。
  例如 `resetGain` 返回 `Decimal`,`onReset` 的 `gain` 就应标 `Decimal`。
- `_Layer` 已替换为 `LayerRef`(`LayerId | Layer`,见 data/types.ts);需要接受 undefined 的调用处显式写 `LayerRef | undefined`,新代码不要再使用 `_Layer`。
