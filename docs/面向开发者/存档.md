# 存档与校验

> 面向开发者。存档相关设计,以【代码】为准。

## 一、序列化

- **Decimal 不可直接 JSON 序列化**。保存时 `markDecimals` 深度遍历把 `Decimal → {$d: 字符串, $l: layer}`;
  读档 `unmarkDecimals` 只还原 `$d` 标记,普通字符串不误转。
- 层0 Decimal 存 `sign*mag` 的精确字符串,用 `fromComponents_noNormalize` 按位还原,往返**位精确**
  (break_eternity 的 `toString` 对 `|mag|<1` 会丢 ~1ulp)。
- 压缩:`lz-string` 的 base64 输出。

## 二、校验码

- `save/checksum.ts`:对 `markDecimals` 后统一序列化的结果做多项式哈希,保存/加载走同一基准。
- `version >= CHECKSUM_VERSION` 的存档强制校验,旧存档跳过。
- 定位:**完整性校验(检测损坏/手改),不是反作弊**——算法公开,源码必然可还原。

## 三、导入防穿越

- `lastPlay > now` → 存档来自未来;
- `firstPlay > lastPlay` → 时间异常;
- `firstPlay < EARLIEST_SAVE_TIME` → 创建时间过早。
  均拒绝导入。

## 四、种子随机

- `player.seed` 在导入/加载时 `seedRng(seed)` 重置 `save/rng.ts` 的模块级状态。
- 可玩性随机(如签到)用 `seedInt`,不能被 SL 或重写 Math.random 控制。滚动新闻仍用 Math.random。

## 五、存档字段兜底

- 读档时先把**一份空白存档的默认值铺在下面**,再套用导入的存档:`Object.assign(player, initializeSave(), saveFile)`(见 `save.ts load()`)。
  这保证旧档没有的字段回到默认值,而不是沿用上一个存档的值(否则导入 v0.1.0 存档后仍会带着已购买的无限升级)。
- 铺完默认值后对易缺失/易非法的字段再做兜底:`seed`、`offlineMode`、`layerSubtab`、`checkin{lastDay,streak}`、`quizLastAt`、`infinityTab`、`infinityBestRate` 等。
  v0.1.2 新增的无限字段(`infinityPoints`/`infinityResets`/`infinityUpgrades`/`infinityRunTime`/`infinityBestResetTime`/`totalInfinityPoints`)由 `initializeSave` 默认值兜底(0/0/[]/0/∞/0);其中 `infinityRunTime`(本次无限经历的时间)由 v0.1.1→v0.1.2 迁移设为总游戏时间(`migration.ts`,判断 `'infinityRunTime' in save`),使该时间从存档时刻起累计。
- `automations`(层级自动化)与 `metaAutomations`(元层自动化)的配置由各自的注册表兜底:元层按 `MetaAutomationDef.sanitizeCfg` 逐项补齐(未知id按自动重置形状);层级配置在读取时按注册表类型补齐(`getLayerAutomation`)。**不新增字段**。
- 旧档迁移:`migration.ts` 的 `migrations` 数组,按版本区间注册:
  - v0.1.0 → v0.1.1:隐藏成就标记 `secretFlags` 迁移为直接解锁对应成就(奖励固定1知识)并删除该字段;普通挑战多激活时只保留编号最大的一个(挑战互斥)。

## 五之二、数值校验与写档保护

`save/validate.ts` 的 `findInvalidValues(target)` 检测 NaN 与非法数值,判据**由空白存档的形状派生**(不维护第二份字段清单,新增字段写进 `initializeSave`/`initializeLayer` 即自动覆盖):
Decimal 字段必须是合法 Decimal,判据只有两条:**不是 NaN**、**layer 是整数**(`mag` 不是尾数大小而是十进制指数,`|值|<1` 时为负数,如 `new Decimal(1e-20)` 的 `mag=-20` 属正常;`Infinity` 合法,如 `infinityBestResetTime` 初始为 `dInf`,故跳过非有限 layer);基础类型字段必须同类型;数组按空白首项校验元素(`dimensions` 的 `[Decimal,Decimal]`);**按 id 存的记录表**(空白对象的键全为非负整数,如层级表)空白之外的键按"空白首个值"当模板校验;**字段名做键的对象**(存档根对象、`checkin`、`autoGlobal` 等)不校验额外键的类型。
任何位置出现的 Decimal 都会被深入检查(含 `challenges.c1`、`buyables[7]` 这类记录表里的值),所以额外键里只放过"非 Decimal 的其它类型"。已知不覆盖:记录表里"该是 Decimal 却写成 number"这类错误(形状未知,无法判定)。

> 为什么不校验字段名对象里额外键的类型:旧存档常残留当前代码已删除/改名的字段(实测 v0.1.2 存档里有 `checkinStreak`/`lastQuizTime`/`easterEggs`/`points` 等 10 个),把它们的类型当错误会把**所有旧档**挡在门外。

**写档裁剪**:`stringify()` 会先 `pruneToBlankShape(marked)` 再算校验码,把**空白档里没有的字段裁掉**(顶层旧字段、层级对象上的多余字段、`checkin`/`autoGlobal` 的多余键),因此旧档残留字段的值默认丢弃、不会被继续写下去。动态映射的键全部保留(层级表、挑战表、自动化配置、可购买表等),`pendingQuiz` 这类形状不定的值原样保留;数组只按元素模板裁剪、**不按空白长度截断**(维度矩阵长度会随机制增长,如元维度提升加维度)。读档校验(`verifySave`)不裁剪——它算的是存档里原本那份对象的校验码。开发构建下第一次裁剪会写一条 warning 日志列出被丢掉的顶层字段(新字段忘了加进 `initializeSave` 的兜底提示)。

- **写档**:`localSave(slot)` 在写入前调用它,**有问题就拒绝写入**并把问题记在 `getLastSaveProblems()`(原槽位保持上一次的好存档,比"写坏档再报警"安全)。UI 侧统一走 `app/saveActions.ts` 的 `saveGame()`:问题内容**首次出现**时写 error 日志(列出全部问题)并弹一次 `openAlert`;同一个问题再次出现只写 warning 日志(提示导出存档),不再弹窗;保存成功后签名清空,下次再坏又会提示。**导出**(字符串/文件)不受影响:照常导出当前状态,便于排查;导出前的同步写档失败是静默跳过的。
- **读档**:`load()` 在写入 player 前校验补齐后的对象,有问题返回**错误码 102**(`导入失败!存档中存在非法数值!`);读档路径已铺过默认值,故旧档缺失字段不会被误判。**从输入框/文件导入**失败只写 error 日志(玩家手里已有存档文件,不需要导出提示)。
- **读档失败的处理(启动 / 从槽位读档)**:`localLoad()` 返回结果码(0 成功 / `LOAD_EMPTY` 无存档 / 其余为错误码)。失败时:
  1. 写 error 日志(带错误码);
  2. `app/saveActions.ts` 的 `handleFailedLoad(code, slot)` 弹确认框:`槽位 n 的存档加载失败(错误码 xxx)。你可以导出存档文本(之后该槽位会被新存档覆盖),或点击"跳过"清空该槽位。`
     - **导出存档文本**:导出 `getRawSaveString(slot)` 的原始字符串为文件(不经序列化),槽位不主动清空,但**不再受保护**(启动路径下的后续自动保存会覆盖它);
     - **跳过**:`clearSlot(slot)` 删除该槽位的存档。
  3. 从**其它槽位**读档失败时不会切换槽位,当前槽位的自动保存照常(读档前已把当前进度存回当前槽位)。
- **"等待玩家选择"期间为什么不用禁写标记**:`main.ts` 把 `setInterval(autoSaveLoop)` 放在对话框关闭之后(空槽位/读档成功则立即开始),等待期间游戏在跑但**没有任何自动写档路径**,坏档不会被空白档覆盖;对话框关闭后该槽位即不再受保护(符合"发现了问题就解决,不无限期保护坏档")。这也是为什么没有"禁写槽位"这类状态:省掉了一处需要跨模块同步的存档相关状态。
- 错误码一览:101 格式不正确(含解压/JSON 解析失败、缺少 `layers`)、102 含非法数值、250 校验码不符、301 存档来自未来、302 时间异常、303 创建时间过早、400 迁移出错。加载失败**不会**用新档覆盖原槽位。

## 五之三、层级结构的读档校验

- `player.layers` 的键是**规范坐标字符串**(去前导零,如 `'0'`、`'1,0'`、`'1,5'`),值一律是层级对象(**不含空占位**;某槽位没有层级就是没有这个键)。规则详见 [层级系统.md](./层级系统.md)。
- 读档时依次执行(见 `save.ts load()`):
  1. `sanitizeLayers()`:**把补零等非规范写法归一化**(`'0,5'`→`'5'`、`'0,0'`→`'0'`,无损),删除非法键(非整数/负数/空串)与空值,保证同一层级只有一种坐标写法;
  2. `clearTempLayers()`:临时层不入档,清空后由下一次结构阶段按新层级重建;
  3. `invalidateLayerOrder()`:失效 `access/layerGraph` 的顺序索引缓存(该缓存另有键集合签名自校验,漏调会自愈);
  4. `layerSubtab` 兜底:指向不存在的层级时回落为 `[0]`。
- **跨层/阶/gap 不新增存档字段**:阶由坐标派生、高度差由 `level` 派生、跨层底数是全局槽位。
