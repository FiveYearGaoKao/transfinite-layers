# 存档与校验

> 面向开发者。存档相关设计,以【代码】为准。

## 一、序列化

- **Decimal 不可直接 JSON 序列化**。保存时 `markDecimals` 深度遍历把 `Decimal → {$d: 字符串, $l: layer}`;
  读档 `unmarkDecimals` 只还原 `$d` 标记,普通字符串不误转。
- 层0 Decimal 存 `sign*mag` 的精确字符串,用 `fromComponents_noNormalize` 按位还原,往返**位精确**
  (break_eternity 的 `toString` 对 `|mag|<1` 会丢 ~1ulp)。
- 压缩:`lz-string` 的 base64 输出。

## 二、校验码

- `save/checksum.ts`:对 `markDecimals` 后统一序列化的结果做多项式哈希,保存/加载走同一基准。
- `version >= CHECKSUM_VERSION` 的存档强制校验,旧存档跳过。
- 定位:**完整性校验(检测损坏/手改),不是反作弊**——算法公开,源码必然可还原。

## 三、导入防穿越

- `lastPlay > now` → 存档来自未来;
- `firstPlay > lastPlay` → 时间异常;
- `firstPlay < EARLIEST_SAVE_TIME` → 创建时间过早。
均拒绝导入。

## 四、种子随机

- `player.seed` 在导入/加载时 `seedRng(seed)` 重置 `save/rng.ts` 的模块级状态。
- 可玩性随机(如签到)用 `seedInt`,不能被 SL 或重写 Math.random 控制。滚动新闻仍用 Math.random。

## 五、存档字段兜底

- `Object.assign(player, saveFile)` 后,对易缺失的字段做兜底(见 `save.ts load()`):
  - `seed`、`offlineMode`、`layerSubtab`、`checkin{lastDay,streak}`、`quizLastAt` 等。
- 旧档迁移:`migration.ts` 的 `migrations` 数组,按版本区间注册:
  - v0.1.0 → v0.1.1:隐藏成就标记 `secretFlags` 迁移为直接解锁对应成就(奖励固定1知识)并删除该字段;普通挑战多激活时只保留编号最大的一个(挑战互斥)。

## 六、槽位

- 10 个存档槽位,槽位号存 localStorage,摘要信息见 `getSlotSummary`。
- 硬重置:`hardReset()` 用 `initializeSave()` 覆盖 player 并立即保存。
