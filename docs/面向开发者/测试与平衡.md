# 测试与平衡

> 面向开发者:改数值、加机制之后怎么自证没跑偏。工具都在 `scripts/`(不参与构建,约定见 [开发规范](./开发规范.md) §二.13)。

## 一、按问题选手段

| 要回答的问题                         | 手段          | 命令                                                                                  |
| ------------------------------------ | ------------- | ------------------------------------------------------------------------------------- |
| 价格/曲线/效果/存档/成就是否仍然自洽 | 对撞式断言    | `npm run check`(或 `check:pricing`/`check:effects`/`check:save`/`check:achievements`) |
| 改了数值后进度趋势如何               | 无头模拟      | `node scripts/run-ts.mjs scripts/sim.ts [分钟数] [步长秒] [打印间隔秒]`               |
| **只靠现有机制能走多远(终局)**       | 模拟玩家+模拟 | 上面的命令再加 `--bot=phased --fresh`,口径见 §五                                      |
| 界面/手感/交互是否正常               | 人手动过一遍  | 见 §四                                                                                |

## 二、无头模拟(sim)

- sim 调用的是真实的 `gameLoop`(`app/core.ts`),帧内顺序与游玩完全一致,不在脚本里重抄一遍;
- 起点存档:`--save=<文件名>` 从 `saves/` 目录下的**基准存档**开始(见 [saves/README.md](../../saves/README.md));不填则先尝试载入仓库根目录下的真实存档——所以"从真实进度继续调""从基准档继续调""从零开始调"只差一个起点;
- 读输出:
  - `[层级]` / `[无限]` / `[挑战]` / `[成就]` 行是**进度时间线**:每解锁一层、每次无限重置、每次挑战完成、每批成就解锁各打一行,调平衡主要看这些时间点;阶段式策略还会打 `[开局]`/`[层级1]`(层级1的重置节奏:收益、距上次、能量)与 `[支线]`(拿到刻意成就)两种诊断行;
  - 指标快照每 `打印间隔秒` 一行(见 §五的指标表);`层0峰值` 是该取样区间的峰值,判"增长"看它而不是瞬时值;
- 参数与取舍:`步长秒` 缺省 1(比真实的 1/60 粗,换来速度);要复现"短时间内的自动化反复触发"就用 `0.0167`。10 分钟游戏时间、步长 1 秒约需 15 秒现实时间;
- 常用开关:`--bot=phased|greedy|none`(缺省 none=挂机观察)、`--fresh`(无视真实存档从零开始)、`--max-step=秒`(无动作时步长放大的上限,缺省 60;**做策略对比时用 `--max-step=1` 固定步长**,否则机器人"没事就不操作"会被压成 60 秒一次点击)、`--no-challenges`(机器人不主动进挑战)、`--unlock-gate=点数`、`--reset-mult=倍数`、`--verbose`(附各层级状态,诊断用);
- 阶段式策略专用开关:`--opening=invest|fast`(开局打法,见 §5.1)、`--open-gain=N`(invest 要求的前两次重置收益,缺省 11)、`--next-gain=N`(解锁层级2及以上要求的**临时层收益**,缺省 1=下层 1e4 点数)、`--buy-amount=one|max`(每次买1个/买最大,缺省 max)、`--no-a24`(不做 a24 支线)、`--hunt-dt=秒`(抓 a24 窗口时的步长,缺省 1/60;调大=降低模拟玩家的"手速")、`--a27`/`--a35`(刻意成就支线);
- 挂机观察(`--bot=none`)只对**已经起步的存档**有意义:空白档既没买过维度也没开自动化,数值不会动;
- 从真实存档继续做实验时加 `--no-challenges`:贪心会一上来就进挑战,而进挑战会强制重置、无限挑战更是直接无限重置(实测把 9 层推平成 1 层,普通挑战完成记录也被清);
- 想从零开始也可以把真实存档临时移走(sim 会打印"未找到真实存档"),或直接加 `--fresh`。

### 基准存档(存档银行)

长测与对照实验的统一起点是 `saves/` 里的基准档(开局 / 解锁挑战 / 第 1 次无限 / 解锁无限挑战 / 解锁元维度提升 / 世界容量上限),由机器人跑到各阶段节点导出:

```sh
npm run saveBank                    # 从空白档跑到各阶段并导出(阶段没跑齐时会报出来)
node scripts/run-ts.mjs scripts/sim.ts 60 1 60 --bot=phased --save=TransfiniteLayers-v0.2.0-baseline-03-infinity.txt
```

命名、阶段判定与导入步骤见 [saves/README.md](../../saves/README.md);机器人策略改了以后要重跑 `npm run saveBank`,否则基准档与当前策略不是同一个起点。

## 三、对比两次改动

1. 固定起点(同一个基准档或真实存档)与固定参数,先跑一次,记下时间线作为基线;
2. 改完再跑一次,比"到达同一进度所需的时间"与收尾的每层数字;
3. 结构不该变的部分再跑 `npm run check` 兜住不变量(价格/曲线、效果管道、存档、成就);
4. 汇报时给出**起点存档 + 参数 + 改前/改后时间线**,不要只给结论。

## 五、模拟玩家与终局测试

### 5.1 模拟玩家(bot)

- **契约**:机器人只调用"按钮背后那层"的函数(`logic/` 的购买/重置/挑战/无限/知识/指令,与 `app/uiActions` 同源),不用调试指令、不直接改 `player` 状态——否则"终局"没有意义;
- 代码在 `scripts/bot.ts`:`nonePolicy`(挂机观察)/ `greedyPolicy`(纯贪心)/ `phasedPolicy`(阶段式)三个策略 + 模拟引擎 `runSim`;三个策略共用同一套动作(`makeActions`),区别只在"何时解锁/何时重置"的钩子;
- **假时钟**:引擎把全局 `Date` 换成"起点 + 已过的现实时间",签到(自然日)、答题冷却、日志时间都按它走;引擎还负责 `realTime` 累加与 `applyTimeResources`(加速/时间扭曲),与 `mainLoop` 同一套规则,所以机器人**不能免费加速**;
- 每步按固定顺序尝试:知识收入(签到/答题)→ 时间类(知识换离线时间、存加速时间、选加速档位)→ 买知识升级 → 买无限升级 → 挑战 → 解锁新层级 → 层级重置 → 购买(升级优先,再按 `buyOrder` 买维度与可购买);
- 参数(`GREEDY_DEFAULTS`):`resetMult` 收益倍率(2)、`resetTime` 停滞放宽(1800s)、`infinityGain` 无限重置最低收益(1)、`challengeTimeout` 挑战超时(7200s)、`challengeStallTime` 挑战内停滞判据(900s)、`challenges` 是否主动进挑战(是,`--no-challenges` 关掉)、`unlockGate` 解锁新层级的最低层级0点数(1e100,理由见下)、`buyPerStep` 每步买几级知识升级(1)、`buyOrder` 维度购买顺序(asc=维度1优先)、`buyAmount` 每次买1个还是买最大(max)、`knowledgeToTime`/`boostReserve` 知识与时间资源的换算;
- **四条配置原则**(都由实测标定,理由随附):
  1. 层级重置按"够本"判(见 §5.2 的重置规则一节):收益达不到要求就不重置,不按时间兜底——按下层 `resetTime` 或"收益不低于上次"触发的重置会把下层进度与本层能量反复清零,层0峰值不再增长;
  2. 重置的基准取**历史最佳收益**而不是当前点数:买维度会把点数花到 0,拿当前点数当基准会让每一帧都"够本",同样是抖动;
  3. **别急着解锁新层级**:解锁会擦掉本层以下的所有进度。实测 `--unlock-gate=1`(一够条件就解锁层级2,37 分钟解锁)时 1 小时层0峰值只有 **e20.6**,而等到 a28(1e100)之后才解锁是 **e66.3**——差 45 个数量级。故 `unlockGate` 缺省 1e100(层级1 的首次解锁不设门槛);
  4. **成就 a24 是硬门槛**:层级2 一旦重置就会把层级1 点数清零,没有 a24(每层重置保留 1 点数)时层级2 的能量加成长期没有对象可乘,多层反馈链起不来。

#### 5.1.1 阶段式策略(`--bot=phased`)

把人工开局写成状态机,在贪心动作之上加"阶段性门槛 + 成就支线":

- 阶段:`layer0`(层级1之前)→ `layer1Open`(层级1的前两次重置)→ `progress`(正常推进,即贪心规则);阶段名会打进指标表;
- **开局打法**(`--opening`,只影响层级1的前两次重置):
  - `invest`=人工打法:层级1**一够条件就解锁**(人工约 2 分钟),之后的**前两次层级1重置**攒到 `openGain` 才做,且第 1 次重置后只买维度1、第 2 次重置后才买维度2(维度1 价格 1 点、维度2 价格 10 点,故 11 = 两次购买的总价);
  - `fast`=解锁后一够条件(收益≥1)就重置层级1(多次快速重置);
  - 实测对比见 §5.2;用 `invest` 时开局时间线与手点基本重合:层级1 **1:39**(手点 2 分)、a24 **24:25**、层级2 **31:11**(手点 30 分);
- **a24 支线(必做)**:a24 的效果是"每层重置后保留 1 点数"。没有它,层级2 一旦重置就会把层级1 点数清零,层级1 要等下一次层级1重置才有维度 → 层级2 的能量加成(作用于层级1 维度)就长期没有对象可乘,多层反馈链断掉。它的条件是**层级1重置时层级0 的 `resetTime < 1 秒`**,即层级1重置后层级0 能在 1 游戏秒内重建到 1e16 点数——只有层级1 的能量已经很大时才可能。做法:每次层级1重置后开一个 1 游戏秒的窗口,窗口内把步长压到 `huntDt`(缺省 1/60)并且**只看 `canReset` 就重置**;
- **a27 支线**(`--a27`,缺省关):层级1能量恒为 0 时一次重置拿 ≥100 点 → 到手前完全不买层级1维度(能量只由维度1产出)。代价是丢掉层级1的能量加成,推进明显变慢,属于"刻意操作";
- **a35 支线**(`--a35`,缺省关):层级2重置会把层级1 的 `resetCount` 清零,故在层级2之后把层级1的重置门槛抬到 1e4,保证"层级1的下一次重置"就满足条件;
- **层级2的解锁(阶段3的开头)**:解锁层级2及以上**不看层级0点数**,而是"**a24 到手 + 临时层收益 ≥ `nextLayerGain`**"(缺省 1)。临时层收益 =(下层点数/1e4)^0.25,故 `nextLayerGain=1` 就是作者的路线"**有 a24 + 1e4 层级1点数就可以重置了**";也可以等更大的收益再重置(`--next-gain=N`,收益 N 需要下层 1e4·N⁴ 点数);
- **挑战(阶段3的后半)**:a28(1e100 层级0点数)解锁挑战页,机器人按 c1→c5 顺序做,但加了四道闸:
  1. **要"目标层已经买出维度3"**(`challengePrepareDim`,约 100 点数):进/退挑战会强制重置目标层并把目标层以下的升级**全部清掉**,但**不动目标层自身**——目标层的维度链(维度3→2→1→能量)会留下来,靠它才把下层重新拉起来(人工经验:层级2 攒约 100 点数买出维度3就能打 c1,不需要 u9);
  2. **要"以前轻松达到过目标"**(挑战外的目标资源峰值 ≥ 目标×`challengeReady`=10),否则进去就是白扔一轮;
  3. **推进式超时**:目标资源 900 秒没涨到 1.5 倍才算停滞退出,硬上限 3600 秒(原来固定 1800 秒,常在"再攒一轮就完成"时退掉),退出后冷却 1800 秒再试;
  4. 只做普通挑战:无限挑战会强制无限重置(整局重开),不属于这一段。
- **购买模式**:`--buy-amount=one|max|fill`,阶段式策略开局用 `one`(逐个人工点击式)、之后用 `fill`——**先把每个维度都买出 1 个再接"买最大"**,否则 `asc+买最大` 会把全部预算砸在维度1上,新解锁的层级永远买不出维度2/3(实测层2 一直卡在"只有维度1")。

#### 重置规则与游戏自动化的对应

机器人的层级重置规则(`actReset`,从高层往低层):

1. 必须 `canReset`(本层收益 > 0);
2. 满足任一:① 本层 `bestPoints == 0`(被更高级重置后的第一次)→ 立即重置;② **本次收益 ≥ 本层"历史最佳收益" × `resetMult`**(缺省 2);
3. `resetTime` 的"停滞放宽"缺省**关闭**(Infinity)。

所以它是**倍率型为主 + "首次放行"** 的混合,基准是**历史最佳收益**而不是当前点数。与游戏自动化的自动重置条件(`logic/automations.ts`)对照:

| 自动化条件 | 含义                                | 机器人能否对应                    |
| ---------- | ----------------------------------- | --------------------------------- |
| 时间       | 下层 `resetTime` ≥ time             | 可对应(现在只在 a35 支线里用)     |
| 点数       | 本层收益 ≥ point(绝对值)            | 可对应(开局"前两次≥11 点"就是它)  |
| 倍率       | 本层收益 ≥ **本层当前点数** × mult  | 语义不同:机器人用的是历史最佳收益 |
| 幂次       | 本层收益 ≥ **本层当前点数** ^ power | 同上(与"倍率"各自独立的条件)      |

- 四个条件可以按"任意/全部满足"组合,是玩家可控的设计;机器人只是换了一种判据(历史最佳收益 + "首次放行"),并不是说自动化写错了;
- **幂次把常量倍率换成"当前点数的 `power` 次方"**,即倍率随持有量自动放大:后期"x100 太小、调高又跑不起来"靠它解决。`power=1` 等价于 `mult=1`,`power>1` 的门槛涨得更快(重置更慢),`power<1` 涨得更慢(重置更急);`power` 只在有限且 >0 时参与判定(否则视为该条件未生效)。能否在后期持续放大取决于 `power` 与实际收益曲线,**必须实测**(有效范围与默认值待长测扫描);
- 用 `bestPoints` 而不是当前点数的原因只有一个:买维度会把当前点数花到 0,拿它当基准在**前中期**会退化成"每步都够本"(§5.2 的重置规则一节);
- 人工开局那条"前两次重置拿至少 11 点数"是**绝对点数条件**,可以直接写进自动化;机器人把它放在阶段机的开局门槛(`layer1Gain`)里,而不是通用规则里。

**实测:层级1能量与 a24 的关系**(invest 打法,固定步长 1 秒,从零开始):层级1的 `u7 能量保留`(价格 500)到手之前,每次层级1重置都会把层级1能量清零,多层复利起不来;买到 u7 后能量单调累积,约 2~3 次重置(能量 e8 上下)后层级0 的重建时间就掉到 1 秒以内,a24 随即到手(本次为 t≈31 分)。这也是"层级1 的重置节奏 = 前中期的主线"的直接证据。

**实测:层级2的解锁时机**(`nextLayerGain` 扫描,invest 开局,固定步长 1 秒):

| `--next-gain`     | 解锁层级2 | 层0峰值 1 时 | 3 时 | 6 时      | a28 到手   |
| ----------------- | --------- | ------------ | ---- | --------- | ---------- |
| 1(下层 1e4 点)    | 37 分     | e46          | e73  | e94       | 未到       |
| 11(下层 1.5e8 点) | 77 分     | e66          | e80  | **e99.6** | 未到       |
| 100(下层 1e12 点) | 4.5 时    | e66          | e86  | e99       | 5 时 39 分 |

- 三种设置最终都在 a28/e100 附近会合(说明"什么时候解锁层级2"在 6 小时尺度上不是决定性的);**但解锁越晚、前期层0峰值越高**(解锁会清掉层级0的加速器/加倍器,收益要靠层级2的能量慢慢还回来);
- 作者的路线(`--next-gain=1`)在 3 小时处比 `=11` 低约 7 个数量级,6 小时后只差 5 个;要"早开挑战"就得接受这段回撤。

**实测:挑战阶段的两个坑**(都是模拟跑出来的):

1. **进挑战的门槛**(对齐人工打法):目标层要**先买出维度3**(约 100 点数,`challengePrepareDim`)、目标资源层的**能量要 ≥1e16**(a27 的门槛,`challengePrepareEnergy`)、挑战外的目标资源峰值要有目标的 10 倍(`challengeReady`)。挑战的强制重置**不动目标层自身**,所以目标层的维度链是重建下层的唯一依靠;
2. **进得去 ≠ 做得完**(当前阻塞点):c1 里层级1点数只从 15 涨到 3966(1 小时,每次翻倍、间隔从 3 分拉长到 11 分),而第一次完成需要 1e5 → 还差约 5 次翻倍,期间每次失败退出都会把下层清空,于是**挑战完成数长期为 0、层数锁在 3 层**。差距在"挑战内的操作顺序",不在门槛。**挑战内打法仍未定**,待对照实验的项目:进挑战后先重买 u7/u8、层级0 是否改用"买最大"、是否要求上层 u1/u2/u3 齐备。

**判定当前点数的成就一律写成"重置触发"**:层级 k 的点数只由更高层的重置发放(`logic/update.ts`:层级0 的维度1产点数,层级 k≥1 的维度1产能量),而成就检查在帧末、自动购买在它之前——自动购买全开时刚发下的那 1 点会被同帧买掉,`getPoints([k]).gte(1)` 这种写法不会成立。故"获得至少 N 个层级 k 点数"类成就(a16/a25/a34/a44/a66/a77)用 `trigger: 'reset'` + `gotLayerPoints(ev, [k])` 判定(看本次重置的 `gain`,发生在发放之前);层级引用一律用绝对高度,不用坐标。a78 是例外:它的条件是"尝试解锁层级10"(0 阶窗口填满时点解锁被拒绝),故是 `trigger: 'manual'`,由 `app/uiActions` 在拒绝时解锁。

**后期自动重置的固定倍率问题(设计层面,不是 bug)**:自动重置有四个可组合的条件(时间/点数/倍率/幂次,任意或全部满足),玩家可以自己配成"倍率且点数"之类;但**倍率本身是常量**。后期(层级多、层级1~5点数 >1e20)会同时遇到:一次重置只在指数上加不到 10%(x100 太小)、而一次重置至少占 1 帧、且层级n重置会把层级1~n-1点数清到 <100 → 必须走"买满 n-2 → 重置拿 n-1 资源 → 再买满 n-2"三步才能做下一次层级n重置;早期把倍率调高又会让自动化跑不起来。解法方向是**幂次**(收益 ≥ 当前点数^power,见 §5.1 的重置规则一节);"不需要重置就能获得点数"的方案会削弱层级本身的意义,不采用。

### 5.2 人工基线(校准用)

**手点基线**(当前用于对齐开局):**层级1 约 2 分钟**、**层级2 约 30 分钟**解锁;手打进 c1 时的参考状态是"层级2 已购维度 2/1/1/0、升级 u1+u2(u1 尽早买)、可购买不动(b11 无用、b12 买不起),层级1 能量略高于 1e16"。模拟玩家的 `invest` 开局已经与它基本重合:层级1 **1:39**、a24 **24:25**、层级2 **31:11**。

**终局口径**:**不加新机制能到层级几**(0 阶窗口能爬到多高)——计划是不靠新机制到层级 7~8、靠一次元维度提升(每层解锁维度5)把 0 阶窗口填满(层级 0~9 都在,即到达世界容量上限);如果现有机制就能填满,说明挑战奖励与无限升级需要削弱。填满后再点解锁会被拒绝(规则见 [层级系统.md](./层级系统.md) §六)。

**v0.1.5 后期存档的用途**:它已经跑到 9 层、198 次无限重置、c1 完成 38 次,和"终局时长"无关,**只能当"层间结构/数值量级"的参照**(例如层级1 能量 e1103、层级0 加速器 984 级),不能当基线。

#### 开局打法对比:人工打法 vs 多次快速重置

命令(两次只差 `--opening`):`node scripts/run-ts.mjs scripts/sim.ts 180 1 1800 --bot=phased --opening=invest|fast --fresh --max-step=1`,指标取**层0峰值**(区间峰值,见 §5.3):

| 打法                           | a24 到手 | 30 分 | 1 小时 | 1.5 小时 | 2 小时 | 3 小时    |
| ------------------------------ | -------- | ----- | ------ | -------- | ------ | --------- |
| `invest`(前两次重置攒到 11 点) | 30:54    | e38.9 | e66.3  | e74.0    | e78.9  | **e86.4** |
| `fast`(够条件就重置)           | 39:38    | e40.3 | e62.9  | e72.8    | e76.7  | e82.3     |

- `fast` 在前 30 分钟略领先(重置更密 → 层级1点数来得快),但 `invest` 从 1 小时起稳定领先,3 小时时高约 **4 个数量级**,a24 也早 9 分钟;
- `invest` 在前两次重置就拿到 11 点(正好买下维度1+维度2),层级1 的维度/能量复利更早起动,层级1的重置次数也更少(1 小时约 40 次 vs 80+);两种打法的节奏差可以直接看 `[开局]`/`[层级1]` 行里的"距上次";
- 结论:**"前两次重置攒到 11 点、先维度1再维度2"确实比"多次快速重置"更快**,与作者的体感一致;
- 注意:a24 的到手时间在两种打法之间会随步长互换(±6 分钟),但层0峰值一致地是 `invest` 领先;**不要用单一的 a24 时间点下结论**。

#### 重置规则:只按收益倍率判

`actReset` 的判据是**收益倍率**(本次收益 ≥ 本层历史最佳收益 × `resetMult`),缺省 `resetTime = Infinity` 即**不启用停滞放宽**——停滞放宽会退化成"一超过上次就重置",把层0峰值反复削平:

| 重置规则           | 1 小时层0峰值 | 3 小时层0峰值 |
| ------------------ | ------------- | ------------- |
| 停滞放宽 1800 秒   | e54.9         | e70.3         |
| 只按收益倍率(缺省) | e66.3         | e86.4         |

- "卡死"交给终局判定的停滞检测负责(§5.3),不要用重置规则兜;要启用停滞放宽就用 `--reset-time=秒`(`reset-time=0` 即缺省行为);
- `resetMult` 在 1.5~10 之间对 1 小时结果影响不大(e65~e68),收益倍率不是主要矛盾。

#### 步长标定(dt 取多大才够)

同一配置(`invest`,固定步长)只改 `步长秒`/`--max-step`,30 分钟处的层0峰值:

| 步长(游戏秒) | 30 分层0峰值 | 现实耗时 |
| ------------ | ------------ | -------- |
| 1            | e38.9        | 15 秒    |
| 1/6          | e38.8        | 74 秒    |
| 1/60         | e38.8        | 323 秒   |

→ **1 秒步长足够**:三种步长的结论一致(差 <0.2 个数量级),细化步长并不单调变快(机器人"越勤快"不一定越强)。只有在需要抓"1 游戏秒内"这类窗口时才用细步长(`--hunt-dt`),不要整局都用 1/60。

#### 模拟玩家的"手速"会不会决定 a24?

a24 的窗口只有 1 游戏秒,窗口内的购买频率天然影响"层级0能否在 1 秒内重建"。把窗口步长从 1/60 调到 1/6(相当于每秒只有 6 轮点击,接近真人手速):a24 仍然到手,只是从 30:54 推到 35:22,1 小时层0峰值 e66.7(对 e66.3)——**结论不变**,说明 a24 不是靠"机器手速"刷出来的,而是层级1能量到位后的自然结果。

### 5.3 终局口径

定义:**某项数值在短期内无法显著增长,它就达到终局**(只靠现有机制)。

**当前判定目标**:不加新机制能到**层级几**(0 阶窗口能爬到多高)。计划是不靠新机制到层级 7~8、靠一次元维度提升(每层解锁维度5)把 0 阶窗口填满(层级 0~9 都在,即 `isWorldCapacityReached([-1])`);
填满后再点解锁会被拒绝(什么都不做,只提示"当前世界无法容纳更多层级"),所以 v0.2.0 的可达上限就是层级 9;
1 阶内容实装后这一步改成**进位**(先轮转出层级10,再加深世界、创建 `[1,0]`=ω 并立刻结算一次它的重置,见 [层级系统.md](./层级系统.md) §六),那时的目标才是"多久填满 0 阶窗口并进位"。

- **取样**:每个指标取**窗口内峰值**,与上一个窗口的峰值比较——层级0点数在无限重置后会归零,比瞬时值会把正常循环误判成"不增长";
- **窗口**:1 游戏小时;
- **阈值**:

| 指标类型 | 指标                                                                   | 平台判据                   |
| -------- | ---------------------------------------------------------------------- | -------------------------- |
| 点数型   | 层级0点数、最高层级点数                                                | 峰值不增加 1 个数量级(×10) |
| 货币型   | 无限点数、知识                                                         | 峰值不翻倍(×2)             |
| 计数型   | 世界层级数、无限重置次数、已购无限升级、知识升级总等级、挑战完成总次数 | 连 +1 都达不到             |
| 到顶豁免 | 无限升级(25)、各知识升级 `maxAmount`、普通成就(56)                     | 涨不上去算"到顶",不算卡住  |
| 观察     | 知识收入分解、离线/加速时间、各挑战完成次数、层级结构丰富度            | 只记录                     |

- **卡死(假终局)**:连续 30 游戏分钟"没有任何动作可做且所有指标零增长"→ 单独报出并落盘当时的存档。这是最有价值的输出:它说明缺机制或卡在某个门槛上;
- **结论要写明策略**:终局是"某个策略空间下的终局"。贪心不含成就支线 → 保守下界;阶段式含支线 → 更接近真人。

### 5.5 结果落点

终局结论按 **§5.3 的表格逐项填写**(值 / 到达平台期的时间 / 是否到顶 / 卡住原因),并注明**策略**(greedy/phased)与参数;每次改数值或加机制后重跑并说明变化。填表口径:

| 项         | 填写什么                                                       |
| ---------- | -------------------------------------------------------------- |
| 值         | 各指标在最后一小时窗口的峰值                                   |
| 到达平台期 | 该指标最近一次跨窗口翻倍/进位的时间                            |
| 是否到顶   | 对照 §5.3 的"到顶豁免"清单,区分"到顶"与"卡住"                  |
| 卡住原因   | 卡死上报里的存档 + 当时卡在哪一步(目标层的维度/能量、挑战差额) |

## 六、分工(人 / AI)

- **人的手动修改**:具体数值(升级价格、加成倍率、维度常量、挑战目标、知识/无限数值)。这类改动不必让 AI 经手。
- **AI 的职责**:框架与机制改动必须跑 `npm run check`;只要动了数值,必须给出 sim(必要时带 `--bot=greedy`)的改前/改后对比,而不是"看起来更快了"。
- 平衡目标由人定(例如"到无限约 40 分钟、每层停留时间递减");AI 只负责如实报出观察结果。
