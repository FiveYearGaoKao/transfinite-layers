# 测试与平衡

> 面向开发者:改数值、加机制之后怎么自证没跑偏。工具都在 `scripts/`(不参与构建,约定见 [开发规范](./开发规范.md) §二.13)。

## 一、按问题选手段

| 要回答的问题                         | 手段          | 命令                                                                                  |
| ------------------------------------ | ------------- | ------------------------------------------------------------------------------------- |
| 价格/曲线/效果/存档/成就是否仍然自洽 | 对撞式断言    | `npm run check`(或 `check:pricing`/`check:effects`/`check:save`/`check:achievements`) |
| 改了数值后进度趋势如何               | 无头模拟      | `node scripts/run-ts.mjs scripts/sim.ts [分钟数] [步长秒] [打印间隔秒]`               |
| **只靠现有机制能走多远(终局)**       | 模拟玩家+模拟 | 上面的命令再加 `--bot=phased --fresh`,口径见 §五                                      |
| 界面/手感/交互是否正常               | 人手动过一遍  | 见 §四                                                                                |

## 二、无头模拟(sim)

- sim 调用的是真实的 `gameLoop`(`app/core.ts`),帧内顺序与游玩完全一致,不在脚本里重抄一遍;
- 会先尝试载入仓库根目录下的真实存档:所以"从真实进度继续调"与"从零开始调"只差一个存档文件;
- 读输出:
  - `[层级]` / `[无限]` / `[挑战]` / `[成就]` 行是**进度时间线**:每解锁一层、每次无限重置、每次挑战完成、每批成就解锁各打一行,调平衡主要看这些时间点;阶段式策略还会打 `[开局]`/`[层级1]`(层级1的重置节奏:收益、距上次、能量)与 `[支线]`(拿到刻意成就)两种诊断行;
  - 指标快照每 `打印间隔秒` 一行(见 §五的指标表);`层0峰值` 是该取样区间的峰值,判"增长"看它而不是瞬时值;
- 参数与取舍:`步长秒` 缺省 1(比真实的 1/60 粗,换来速度);要复现"短时间内的自动化反复触发"就用 `0.0167`。10 分钟游戏时间、步长 1 秒约需 15 秒现实时间;
- 常用开关:`--bot=phased|greedy|none`(缺省 none=挂机观察)、`--fresh`(无视真实存档从零开始)、`--max-step=秒`(无动作时步长放大的上限,缺省 60;**做策略对比时用 `--max-step=1` 固定步长**,否则机器人"没事就不操作"会被压成 60 秒一次点击)、`--no-challenges`(机器人不主动进挑战)、`--unlock-gate=点数`、`--reset-mult=倍数`、`--verbose`(附各层级状态,诊断用);
- 阶段式策略专用开关:`--opening=invest|fast`(开局打法,见 §5.1)、`--open-gain=N`(invest 要求的前两次重置收益,缺省 11)、`--buy-amount=one|max`(每次买1个/买最大,缺省 max)、`--no-a24`(不做 a24 支线)、`--hunt-dt=秒`(抓 a24 窗口时的步长,缺省 1/60;调大=降低模拟玩家的"手速")、`--a27`/`--a35`(刻意成就支线);
- 挂机观察(`--bot=none`)只对**已经起步的存档**有意义:空白档既没买过维度也没开自动化,数值不会动;
- 从真实存档继续做实验时加 `--no-challenges`:贪心会一上来就进挑战,而进挑战会强制重置、无限挑战更是直接无限重置(实测把 9 层推平成 1 层,普通挑战完成记录也被清);
- 想从零开始也可以把真实存档临时移走(sim 会打印"未找到真实存档")。

## 三、对比两次改动

1. 固定起点(同一个真实存档)与固定参数,先跑一次,记下时间线作为基线;
2. 改完再跑一次,比"到达同一进度所需的时间"与收尾的每层数字;
3. 结构不该变的部分再跑 `npm run check` 兜住不变量(价格/曲线、效果管道、存档、成就);
4. 汇报时给出**起点存档 + 参数 + 改前/改后时间线**,不要只给结论。

## 四、手动回归清单(改界面/交互时)

- 切页:层级/挑战/知识/自动化/无限/成就/选项各进一次;窄屏(≤700px)与矮屏(≤500px)各看一次;
- 存档:导出→导入往返、槽位切换、坏档提示(是否提示导出备份);
- 购买:手动买一次维度/可购买/升级,确认扣费与效果;
- 自动化:开一个自动购买、关掉、改配置后存读档一次;
- 指令框:`/help`、一条未知指令、`/quiz`(含取消)。

## 五、模拟玩家与终局测试

### 5.1 模拟玩家(bot)

- **契约**:机器人只调用"按钮背后那层"的函数(`logic/` 的购买/重置/挑战/无限/知识/指令,与 `app/uiActions` 同源),不用调试指令、不直接改 `player` 状态——否则"终局"没有意义;
- 代码在 `scripts/bot.ts`:`nonePolicy`(挂机观察)/ `greedyPolicy`(纯贪心)/ `phasedPolicy`(阶段式)三个策略 + 模拟引擎 `runSim`;三个策略共用同一套动作(`makeActions`),区别只在"何时解锁/何时重置"的钩子;
- **假时钟**:引擎把全局 `Date` 换成"起点 + 已过的现实时间",签到(自然日)、答题冷却、日志时间都按它走;引擎还负责 `realTime` 累加与 `applyTimeResources`(加速/时间扭曲),与 `mainLoop` 同一套规则,所以机器人**不能免费加速**;
- 每步按固定顺序尝试:知识收入(签到/答题)→ 时间类(知识换离线时间、存加速时间、选加速档位)→ 买知识升级 → 买无限升级 → 挑战 → 解锁新层级 → 层级重置 → 购买(升级优先,再按 `buyOrder` 买维度与可购买);
- 参数(`GREEDY_DEFAULTS`):`resetMult` 收益倍率(2)、`resetTime` 停滞放宽(1800s)、`infinityGain` 无限重置最低收益(1)、`challengeTimeout` 挑战超时(600s)、`challenges` 是否主动进挑战(是,`--no-challenges` 关掉)、`unlockGate` 解锁新层级的最低层级0点数(1e100,理由见下)、`buyPerStep` 每步买几级知识升级(1)、`buyOrder` 维度购买顺序(asc=维度1优先)、`buyAmount` 每次买1个还是买最大(max)、`knowledgeToTime`/`boostReserve` 知识与时间资源的换算;
- **三条教训**(都是实测出来的):
  1. 层级重置必须"够本"才做:早期版本"每 60 秒必重置"会把下层进度与本层能量反复清零,峰值一小时不涨(抖动);
  2. 重置的基准要用**历史最佳收益**而不是当前点数:买维度会把点数花到 0,拿当前点数当基准就变成"每步都够本"→ 又是抖动;
  3. **别急着解锁新层级**:解锁会擦掉本层以下的所有进度。实测"一够条件就解锁层级2"会把层0 峰值从 e34 打回 e16 并一路走低;等到 a28(1e100)再解锁则能到 e63。故 `unlockGate` 缺省 1e100(层级1 的首次解锁不设门槛)。

#### 5.1.1 阶段式策略(`--bot=phased`)

把人工开局写成状态机,在贪心动作之上加"阶段性门槛 + 成就支线":

- 阶段:`layer0`(层级1之前)→ `layer1Open`(前两次层级1重置)→ `progress`(正常推进,即贪心规则);阶段名会打进指标表;
- **开局打法**(`--opening`,只影响层级1的前两次重置):
  - `invest`=人工打法:解锁层级1(它本身就是第 1 次重置)与第 2 次重置都攒到 `openGain` 才做,且第 1 次重置后只买维度1、第 2 次重置后才买维度2(维度1 价格 1 点、维度2 价格 10 点,故 11 = 两次购买的总价);
  - `fast`=多次快速重置:一够条件(收益≥1)就重置;
  - 实测对比见 §5.2;
- **a24 支线(必做)**:a24 的效果是"每层重置后保留 1 点数"。没有它,层级2 一旦重置就会把层级1 点数清零,层级1 要等下一次层级1重置才有维度 → 层级2 的能量加成(作用于层级1 维度)就长期没有对象可乘,多层反馈链断掉。它的条件是**层级1重置时层级0 的 `resetTime < 1 秒`**,即层级1重置后层级0 能在 1 游戏秒内重建到 1e16 点数——只有层级1 的能量已经很大时才可能。做法:每次层级1重置后开一个 1 游戏秒的窗口,窗口内把步长压到 `huntDt`(缺省 1/60)并且**只看 `canReset` 就重置**;
- **a27 支线**(`--a27`,缺省关):层级1能量恒为 0 时一次重置拿 ≥100 点 → 到手前完全不买层级1维度(能量只由维度1产出)。代价是丢掉层级1的能量加成,推进明显变慢,属于"刻意操作";
- **a35 支线**(`--a35`,缺省关):层级2重置会把层级1 的 `resetCount` 清零,故在层级2之后把层级1的重置门槛抬到 1e4,保证"层级1的下一次重置"就满足条件。

**实测:层级1能量与 a24 的关系**(invest 打法,固定步长 1 秒,从零开始):层级1的 `u7 能量保留`(价格 500)到手之前,每次层级1重置都会把层级1能量清零,多层复利起不来;买到 u7 后能量单调累积,约 2~3 次重置(能量 e8 上下)后层级0 的重建时间就掉到 1 秒以内,a24 随即到手(本次为 t≈31 分)。这也是"层级1 的重置节奏 = 前中期的主线"的直接证据。

### 5.2 人工基线(校准用)

作者本人从零到 v0.1.0 终局(无限/a48,1.79e308 层级0点数)约 **2~3 小时**,操作频率不高、自认非最优。模拟玩家的结果应与这个量级可比:差一个数量级以上说明**策略有问题**(而不是游戏太难),需要先改策略再谈终局。

#### 开局打法对比:人工打法 vs 多次快速重置

命令(两次只差 `--opening`):`node scripts/run-ts.mjs scripts/sim.ts 60 1 600 --bot=phased --opening=invest|fast --fresh --max-step=1`,指标取**层0峰值**(区间峰值,见 §5.3):

| 打法                          | a24 到手 | 10 分 | 20 分    | 30 分    | 40 分    | 50 分    | 60 分    |
| ----------------------------- | -------- | ----- | -------- | -------- | -------- | -------- | -------- |
| `invest`(前两次重置攒到 11 点) | 30:54    | e24.3 | e31.5    | e38.9    | e49.4    | e50.5    | **e54.9** |
| `fast`(够条件就重置)          | 37:07    | e25.4 | e35.4    | e40.3    | e40.3    | e40.4    | e49.4    |

- 前 35 分钟 `fast` 略领先(重置更密 → 层级1点数来得快),但它的层0峰值在 e40 一带**卡了 20 分钟**(收益太小,层级1 的维度/能量复利起不来);
- `invest` 在前两次重置就拿到 11 点(正好买下维度1+维度2),能量复利更早起动,40 分钟后反超,1 小时时领先约 **5 个数量级**;层级1的重置次数也更少(约 40 次 vs 80+),`[开局]` 行里的"距上次"能直接看出两种打法的节奏差;
- 结论:**"前两次重置攒到 11 点、先维度1再维度2"确实比"多次快速重置"更快**,与作者的体感一致;`fast` 只在开局的最初半小时占优。
- 注意:a24 的到手时间在两种打法之间会随步长互换(±6 分钟),但层0峰值一致地是 `invest` 领先;**不要用单一的 a24 时间点下结论**。

#### 步长标定(dt 取多大才够)

同一配置(`invest`,固定步长)只改 `步长秒`/`--max-step`,30 分钟处的层0峰值:

| 步长(游戏秒) | 30 分层0峰值 | 现实耗时 |
| ------------ | ------------ | -------- |
| 1            | e38.9        | 15 秒    |
| 1/6          | e38.8        | 74 秒    |
| 1/60         | e38.8        | 323 秒   |

→ **1 秒步长足够**:三种步长的结论一致(差 <0.2 个数量级),细化步长并不单调变快(机器人"越勤快"不一定越强)。只有在需要抓"1 游戏秒内"这类窗口时才用细步长(`--hunt-dt`),不要整局都用 1/60。

#### 模拟玩家的"手速"会不会决定 a24?

a24 的窗口只有 1 游戏秒,窗口内的购买频率天然影响"层级0能否在 1 秒内重建"。把窗口步长从 1/60 调到 1/6(相当于每秒只有 6 轮点击,接近真人手速):a24 仍然到手,只是从 30:54 推到 35:22,60 分层0峰值 e54.0(对 e54.9)——**结论不变**,说明 a24 不是靠"机器手速"刷出来的,而是层级1能量到位后的自然结果。

### 5.3 终局口径

定义:**某项数值在短期内无法显著增长,它就达到终局**(只靠现有机制)。

- **取样**:每个指标取**窗口内峰值**,与上一个窗口的峰值比较——层级0点数在无限重置后会归零,比瞬时值会把正常循环误判成"不增长";
- **窗口**:1 游戏小时;
- **阈值**:

| 指标类型 | 指标                                                                   | 平台判据                   |
| -------- | ---------------------------------------------------------------------- | -------------------------- |
| 点数型   | 层级0点数、最高层级点数                                                | 峰值不增加 1 个数量级(×10) |
| 货币型   | 无限点数、知识                                                         | 峰值不翻倍(×2)             |
| 计数型   | 世界层级数、无限重置次数、已购无限升级、知识升级总等级、挑战完成总次数 | 连 +1 都达不到             |
| 到顶豁免 | 无限升级(25)、各知识升级 `maxAmount`、普通成就(45)                     | 涨不上去算"到顶",不算卡住  |
| 观察     | 知识收入分解、离线/加速时间、各挑战完成次数、层级结构丰富度            | 只记录                     |

- **卡死(假终局)**:连续 30 游戏分钟"没有任何动作可做且所有指标零增长"→ 单独报出并落盘当时的存档。这是最有价值的输出:它说明缺机制或卡在某个门槛上;
- **结论要写明策略**:终局是"某个策略空间下的终局"。贪心不含成就支线 → 保守下界;阶段式含支线 → 更接近真人。

### 5.4 刻意操作清单(成就支线)

有些成就靠自然推进拿不到,必须刻意操作;其中多条**带数值效果**,不做得出的结论会偏悲观:

| 成就             | 刻意动作(修正后)                                                         | 效果                |
| ---------------- | ------------------------------------------------------------------------ | ------------------- |
| a24 速通高手     | 解锁层级1后**立刻**重置层级1(层级0 `resetTime<1s`)                       | 每层重置保留 1 点数 |
| a27 我需要能量吗 | **不买层级1的维度**(能量恒为 0),攒够本次层级1重置收益≥100 后重置         | 能量指数 +0.01      |
| a35 我需要重置吗 | **先解锁层级2并做一次层级2重置**(它会把层级1 `resetCount` 清零)再刷层级1 | —                   |
| a41 逆流而上     | 专门进 c3 刷层级1能量到 9.89e42                                          | 维度产量 ×10(衰减)  |
| a42 加倍器棋盘   | 中期专门堆 64 个层级0加倍器                                              | b12 底数 +0.2       |
| a45 维度1之力    | 单开一局只买维度1,点数到 1e50                                            | 维度1 ×5            |
| a33 / a47        | 顺带堆 b11、买层级1加速器加成                                            | 小加成              |
| a52 ∞是横着的8   | 精确花到剩 8 IP                                                          | —                   |
| a65 我需要层级吗 | 单开一局不碰层级1(可行性待验证)                                          | —                   |
| a66 转瞬即逝     | **暂不追求**:进 ic5 刷无限重置会把"最佳IP/秒"堆高 → im100 被动IP失衡     | 见 TODO 6.8         |
| 隐藏成就 s11~s23 | 机器人不做(元操作/作弊/刷UI/概率项),全部选做(只给 1 知识、无加成)        | —                   |

- 其中 **a24 已写进阶段式策略并默认开启**(多层反馈链的必要条件,见 §5.1.1);**a27 / a35 是 `--a27` / `--a35` 开关**,默认关闭(它们靠牺牲推进换成就,只在量化支线价值时开);
- 纯贪心策略**不含**任何支线;两类结果的差值,正好量化支线成就的数值价值。

### 5.5 结果落点

终局表的**结论**写在 `docs/面向开发者/终局.md`(值 / 到达平台期的时间 / 是否到顶 / 卡住原因),每次改数值或加机制后重跑并说明变化。

## 六、分工(人 / AI)

- **人的手动修改**:具体数值(升级价格、加成倍率、维度常量、挑战目标、知识/无限数值)。这类改动不必让 AI 经手。
- **AI 的职责**:框架与机制改动必须跑 `npm run check`;只要动了数值,必须给出 sim(必要时带 `--bot=greedy`)的改前/改后对比,而不是"看起来更快了"。
- 平衡目标由人定(例如"到无限约 40 分钟、每层停留时间递减");AI 只负责如实报出观察结果。
